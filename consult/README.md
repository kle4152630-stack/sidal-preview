# 사이달 AI 상담 초안 (결과 창 + 엔진)

누군가 "AI 상담"을 신청하면 뜨는 창입니다. 상황, 고민, 목표를 적고 1~78 번호 하나를 고르면 결과 창이 열립니다. `dist/` 밖의 초안이라 **배포되지 않습니다**(`hub-draft/`, `carousel-draft/`와 같은 방식).

```sh
python -m http.server 8000      # 저장소 루트에서
# http://localhost:8000/ai-consult-draft/index.html
```

## 이게 무엇이고 무엇이 아닌가
- **엔진(`engine.js`)은 대규모 언어 모델이 아닙니다.** 서버·API 키·네트워크 없이, 사이달의 210개 상황·78장 카드 데이터와 규칙으로 상담 글을 조립하는 초안 생성기입니다. 입력은 이 기기 밖으로 나가지 않습니다.
- 더 풍부한 문장이 필요하면 결과 창의 **[AI에게 더 맡기기 (프롬프트 복사)]**로 만든 프롬프트를 Claude·GPT에 붙여 넣습니다. 프롬프트에는 규칙, 입력, 카드, 초안이 들어 있어 AI가 일반론으로 빠지지 않게 합니다.
- "저 정도로 구체적이고 지루하지 않은 AI 상담"을 **자동으로** 내려면 실제 모델 호출(서버 + API 키 + 비용)이 필요합니다. 이 초안은 그 구조를 막지 않도록 입력 형식, 출력 형식, 금지 규칙, 품질 점검을 먼저 고정한 것입니다.

## 운영 방법 3가지 (비용·위험이 낮은 순서)
| 방법 | 하는 일 | 비용 | 사용자 결정 |
|---|---|---|---|
| A. 결과 창 그대로 | 신청 내용으로 결과를 만들고 고객에게 복사해 전달 | 0원 | 없음 |
| B. 반자동(권장 시작점) | 결과 창의 프롬프트를 Claude·GPT에 넣어 다듬고, 운영자가 읽고 고쳐서 전달 | AI 구독 | 전달 채널, 가격(영상 주장은 질문 5,000원 / 20분 3만 원) |
| C. 서버 연결 | 같은 프롬프트를 서버에서 모델 API로 호출. PR #61의 `chatbot-tarot/api/chat.js`가 같은 구조 | API 호출 비용 | **키 발급, 입력을 서버로 보내는 데 대한 동의 문구**(AGENTS.md) |

## 영상(`re_Os7WOGhA`) 기술 비판과 수용
영상의 AI 활용: 고객 질문을 범용 AI(Gemini)에 넣고 답을 다듬어 전달(3:50~4:10), 번호 1~78을 고르게 하고 AI가 카드를 해석(4:56~5:20), 무료 질문을 먼저 돌려 만족하면 유료 20분 상담(24:30~24:50), 결과가 너무 일반적이면 "구체적으로 세 줄 이상"이라고 다시 지시(10:45~10:55). 수익·인원 수치는 모두 출연자의 자기 보고입니다.

| 영상의 기술 | 판단 | 이 초안에서 |
|---|---|---|
| 고객 질문 → AI 초안 → 사람이 다듬어 전달 | **수용** | 운영 방법 B. 결과 창이 초안을, 프롬프트 복사가 AI 단계를, 운영자 점검이 사람 검수를 맡음 |
| 입력을 최소로: 질문 + 번호 | **수용** | 상황·고민·목표 3칸 + 번호 하나 |
| 무료 맛보기 → 유료 연장 | **수용(구조만)** | 결과 창이 맛보기. 유료 연장은 사용자 결정(결제는 PAYMENTS.md) |
| 결과가 모호하면 "구체적으로 세 줄 이상" 재지시 | **부분 수용** | 길이가 아니라 **입력 인용, 사실과 추측 분리, 조건형 7일 계획**으로 구체성을 만든다. 길이를 늘려도 일반론은 구체적이 되지 않음 |
| "구독자 8~9만", "5월·11월에 귀인" 같은 수치·시기 예측(2:40~3:10, 5:29~5:50) | **비판, 불채택** | 근거를 확인할 수 없고 AGENTS.md가 금지. 대신 "만약 A면 B"의 조건형 행동으로 바꿈 |
| 묻지 않은 건강 경고, 성격 단정("워커홀릭·완벽주의", 5:08~5:57) | **비판, 불채택** | 입력에 없는 정보를 지어내는 콜드 리딩(바넘 효과). 이 초안은 입력한 문장만 사실로 쓰고 그 밖은 "단정할 수 없는 것"에 둠 |
| "AI는 컨디션이 없어서 더 정확"(4:27~4:33) | **비판** | 정확성을 검증할 대상(미래·남의 마음)이 아님. 일관성과 정확성은 다르다 |
| "전 남친 속마음 알려줘" 상품(8:55) | **비판, 불채택** | 속마음 단정 금지. 대신 "직접 확인하는 말"을 줌 |
| 한 번의 범용 AI 호출, 안전 장치 없음 | **보강** | 위기 문구 감지 시 해석 중단 + 전문가 연결, 금전·건강 소재는 전문가 안내, 금지 표현 자동 점검 |

웹 조사에서 확인한 근거: AI 타로의 대표 실패는 누구에게나 맞는 말을 하는 바넘 효과이고 사용자 상황과 질문에 의존해야 한다는 설명([Jenova](https://www.jenova.ai/en/resources/ai-tarot-prediction), [18Forty](https://18forty.org/articles/ai-cold-reading-psychic/?print=pdf)). 챗봇이 프로그램임을 알리고, 위기 언어를 감지하면 전문가로 연결하라는 4대 안전장치 제안([Wikidocs 요약](https://wikidocs.net/blog/@jaehong/13288/)). 모두 2차 자료이고, 프롬프트 스키마의 효과를 비교한 측정 자료는 찾지 못했습니다.

## 붙여 준 시스템 프롬프트의 반영
- 페르소나 '사이달', 단정·공포 조장·속마음 확정 금지, 4부 구조, 마무리 문구를 `buildPrompt()`의 기본으로 삼았습니다. 그 위에 엔진이 확인한 규칙(입력 인용, 사실·추측 분리, 조건형 행동, 위기·전문가 안내, 사용자가 적지 않은 사실을 지어내지 않기)을 더했습니다.
- 표기 차이: 붙여 준 글의 `【내 고민에 대 보면】`는 오타로 보여 `【내 고민에 비춰 보면】`로 썼습니다. 기존 `chatbot-tarot`는 원래 표기를 쓰므로 맞출지는 사용자가 정해 주세요.
- 이 프롬프트의 "더 깊은 대화"에 해당하는 AI 실시간 대화는 아직 없습니다(방법 C).

## 구조
```
ai-consult-draft/
  index.html   신청 폼 → 결과 창. 390px 기준, 번호 78개, 운영자용 품질 점검
  engine.js    consult() 상담 조립 · selfCheck() 품질 점검 K1~K14 · buildPrompt() AI용 프롬프트
  card-lens.js 78장 카드별 상황 직결 문장 + 56장 카드별 질문 (영상 화면에서 본 "카드를 상황에 직결" 기법을 단정 없이 옮김)
tests/ai-consult.test.cjs   20개 테스트(CI의 node --test가 함께 실행)
```
**결과 구성(운영자가 준 '사이달' 프롬프트의 4부 구조를 맨 앞에):**
1. 핵심 한 줄 요약 — 목표와 상관없이 맞는 한 문장 결론(90자 이하)
2. 카드가 말하는 것 — 카드 그림, **78장 각각의 "이 카드를 대면" 문장**(그림 속 장면을 이 고민에 비추는 비유, `card-lens.js`), **숫자·궁정 카드 56장 각각의 카드별 질문**
3. 내 고민에 비춰 보면 — 적어 주신 사실 / 아직 확인되지 않은 추측 / 조심할 함정 하나 / 목표와 정할 수 있는 부분
4. 이번 주 해볼 한 걸음 — 행동 1가지 + 이렇게 해봐요(그대로 쓸 문장) + 7일 뒤 확인
- (금전·계약·법률·건강 소재일 때) 전문가에게 확인할 부분 — **접히지 않는 박스**로 항상 보임
- 자세히 보기(접힘): 내가 쓴 말 · 지금 확인되는 것 · 아직 단정할 수 없는 것 · 함정 · 7일 계획(조건형 규칙 2개) · 쓸 수 있는 문장 · 스스로에게 묻기 3개
- 안내(프로그램이 만든 초안임, 면책) + 운영자 마무리 안내

**맨 위 한 줄(리드):** "적어 주신 내용에서 사실로 읽히는 것은 N개, 아직 추측인 것은 M개예요." 입력 문장을 사실과 추측으로 나눈 개수입니다.

**운영자 마무리 안내:** 사용자가 준 프롬프트의 "※ 더 깊은 대화나 1:1 심층 전문가 상담을 원하시면 프로필 링크를 확인해 주세요."를 기본으로 결과 맨 끝에 붙입니다. 바꾸려면 `index.html`의 `SidalConsult.create(…)` 호출에 `{closing: '새 문구'}`를, 끄려면 `{closing: ''}`를 넘깁니다. 위기 응답에는 붙지 않습니다. **이 문구는 "1:1 심층 전문가 상담"이라는 서비스를 약속하므로, 담당자·가격·환불을 정하기 전에는 문구를 바꾸거나 끄는 편이 안전합니다(사용자 결정).**

**품질 점검 K1~K14(주관어 없음):** 금지 표현 없음, 면책, 입력 인용, 행동 4줄, 조건형 규칙 2개, 질문 3개가 물음표로 끝남, 2,400자 이하, 카드 해석, "선택한 고민:" 반복형 없음, 4부 구조가 이 순서로 맨 앞, 한 줄 요약이 한 문장·90자 이하, 해볼 한 걸음이 행동 1가지 구성, 운영자 안내가 맨 끝, 카드 박스에 "이 카드를 대면" 문장 있음. 위기 응답은 109 안내와 카드 없음을 점검합니다.

## 안전 설계와 사용자가 확인할 것
- 위기 문구("죽고 싶", "자해" 등)가 보이면 카드 해석을 하지 않고 **자살예방 상담전화 109**와 전문가·가까운 사람에게 이야기하도록 안내합니다. 109는 웹 검색 결과(국내 24시간 창구로 소개)를 근거로 넣었고, **공식 번호를 사용자가 한 번 더 확인해야 합니다.**
- AGENTS.md는 "스토킹·폭력·신고·수사기관 안내 문구를 서비스에 추가하지 않는다"고 합니다. 이 초안은 그 문구를 넣지 않았고(테스트가 확인), 건강 위기(자해)의 전문가 연결은 "금전·건강·안전 상황은 전문가나 공식 창구를 안내한다"는 같은 문서의 원칙에 따른 것입니다. 이 해석이 사용자 의도와 다르면 알려 주세요.
- 금전·계약·법률·건강 소재는 "카드로 정할 문제가 아니에요"와 함께 공적 상담·전문가 확인을 안내합니다.
- 결과 첫머리와 끝에 "프로그램이 만든 초안"임과 "전문 상담, 의학, 법률 조언을 대체하지 않습니다"를 적습니다.
- 입력은 저장·전송하지 않습니다(`fetch`, `localStorage`, 쿠키를 쓰지 않음을 테스트가 확인).

## 영상 화면에서 직접 확인한 것 (2026-10-26, 브라우저로 4:58~5:27 재생)
영상 속 Gemini 'Gem'의 답은 (1) "상담사 전용 정보" 줄과 고객 전달 글을 분리하고, (2) 친구 같은 반말과 "소름 돋았죠?" 같은 첫머리 후크를 쓰고, (3) "완드 9는 번아웃 직전"처럼 카드를 상황에 직결하고, (4) 성격·외모·수치·시기를 단정했습니다. 이 초안은 (3)을 단정 없는 비유로, (1)을 운영자용 점검으로 가져오고 (4)는 채택하지 않았습니다. (2) 말투는 아직 해요체 하나이며 선택 기능은 다음 작업입니다.

## 한계 (정직하게)
1. **LLM이 아니라 규칙 조립입니다.** 고객마다 완전히 다른 문장을 쓰지는 못합니다. 같은 범주의 조건형 규칙·함정·문장은 정해진 문구라 반복되면 지루해질 수 있습니다. 진짜 맞춤 문장은 방법 B(프롬프트 복사) 또는 C(서버 연결)에서 나옵니다.
2. 상황 매칭은 글자 조합 기반이라 말을 바꾸면 놓치기도 합니다(일반 모드로 답함). 틀린 상황에 붙이는 것보다 안전한 쪽을 택했습니다.
3. 현재 main의 일부 `fact`가 "선택한 고민: …"로 제목 반복형이라, 엔진이 그런 문장은 쓰지 않고 입력 문장으로 대신합니다(PR #23이 병합되면 해결).
4. 실제 휴대폰, 스크린리더, 실제 고객 반응은 확인하지 못했습니다. 이 결과의 효과(만족도, 유료 전환)는 측정 전입니다.
5. 7일 계획의 "내가 정할 수 있는 것과 없는 것 나누기"는 일반적인 정리 기법이지, 이 상황에 맞춘 처방이 아닙니다.
